## Что делает установщик

Запускается от root через `scripts/deploy-admin.sh`. Нужны NVM с Node 22.21.0,
Python 3.9+, Git, npm, PM2 и доступ сервера к GitHub/npm. Использует только
`/home/rm/admin`, `/home/rm/admin-deployments` и процесс `rm-admin`.

1. Берёт эксклюзивную блокировку. Проверяет фактические Node, PM2 ID, cwd,
   интерпретатор, режим одного процесса и исходную HTTPS-страницу входа.
   Полная конфигурация PM2 сохраняется приватно; окружение не печатается.
2. Загружает точный коммит отдельным клоном и проверяет, что это текущий main,
   что реализация почты совпадает с проверенной и что нет GitHub Actions.
   Предполагается отсутствие сторонней установки: не запускайте параллельно
   ручной деплой или другую систему доставки. Блокировка координирует только
   экземпляры этого установщика.
3. Принимает только известные серверные изменения двух файлов роли
   (совпадение с исходным main, коммитом роли или новым релизом) и изменение
   **только верхнего** имени package-lock.json. Неизвестные изменения прерывают
   установку до остановки приложения; файлы не сбрасываются.
4. Создаёт полный независимый `snapshot/`: исходники, .git, dist, node_modules,
   .env, прежние копии и маркеры. Корневой каталог резервов имеет права 0700.
   Проверяет свободное место. Приватные логи и метаданные не отправляйте в GitHub.
5. Переносит нетрековые настройки, файлы и старые копии в отдельный релиз.
   Старые dist/node_modules остаются в резерве, новые собираются через `npm ci`
   и `npm run build`. Почтовый тест выполняется с заглушкой SMTP.
6. В новом .env явно устанавливает `ADMIN_MAIL_ENABLED=false`, сохраняя другие
   настройки. Если SMTP уже включён в окружении PM2, останавливается до установки:
   это требует отдельной проверки конфигурации. `--update-env` не используется.
7. Повторно проверяет неизменность исходников, .env и конфигурации процесса.
   Останавливает только сохранённый PM2 ID, переименовывает прежний каталог в
   `original/`, ставит собранный релиз по прежнему пути и перезапускает тот же ID.
   Аргументы, окружение, интерпретатор и пути логов должны остаться прежними.
   Для логов внутри приложения сохраняет прежние inode через ссылки на original/;
   этот каталог нельзя удалять после установки.
8. Проверяет стабильность PM2 и HTTPS-входа не менее 15 секунд, отсутствие новых
   ошибок в логах. Проверка защищённых карточек/редактора требует отдельной
   авторизованной сессии и автоматически не выполняется. Писем не отправляет.
9. При ошибке после остановки восстанавливает прежний каталог и проверяет
   доступность. Ошибки до остановки оставляют работающую версию без изменений.

Не запускает миграции, не меняет БД, backend, платформу, nginx или лендинг.
На production не запускает браузерные тесты; они проверены отдельно локально.
`pm2 save` и перезапуск остальных процессов не выполняются.

## Запуск с Windows PowerShell

Точные команды с закреплённым SHA установщика выдаются при его публикации.
Скачайте установщик в отдельный локальный каталог, передайте оба файла через
`scp` в новый каталог `/root/rm-admin-deploy-<дата>` и запустите:

```powershell
ssh root@89.108.113.137 "bash /root/rm-admin-deploy-<дата>/deploy-admin.sh deploy 1b0e6e0b8a332225152e11523c13528380e9f663"
```

Пароль SSH, если потребуется, вводится только в запрос вашего SSH-клиента.
Не передавайте его в командной строке. Не отключайте проверку ключа сервера.
При первом подключении проверьте отпечаток доверенным способом.

Успех — строка `INSTALLED <SHA>` и путь резервной копии. `STOPPED` означает
ошибку; не считайте подготовленный каталог установленным обновлением.
При аварийном выключении сервера/SIGKILL автоматический откат невозможен:
используйте сохранённое состояние и ручной откат после восстановления связи.

## Откат

Используйте **тот же загруженный установщик**, который остаётся вне приложения:

```powershell
ssh root@89.108.113.137 "bash /root/rm-admin-deploy-<дата>/deploy-admin.sh rollback /home/rm/admin-deployments/<идентификатор>"
```

Вместо идентификатора подставьте полный путь, напечатанный при установке.
Откат сохраняет неудачный релиз в `failed-<дата>/`, возвращает `original/` на
`/home/rm/admin`, перезапускает прежний PM2 ID и проверяет вход и новые логи.
Повторный откат того же резерва запрещён, если `original/` уже восстановлен.
Резервные копии автоматически не удаляются.

## Проверки самого установщика

```bash
bash -n scripts/deploy-admin.sh
python3 tests/deploy-admin.test.py
```

Тесты используют временные Git-репозитории и файловые каталоги, заглушки PM2,
npm и HTTPS. Проверяют установку, сохранение резервов и параметров, отключённый
SMTP, ручной/автоматический откат, запрет неизвестных серверных изменений и
ошибок в логах. Это не замена проверке реального production.
